## Additions from the second eng review (2026-08-01, post-pivot)

Hosting pivoted to self-hosted Docker Compose (Postgres 17 + Caddy, no Supabase,
no Vercel, no KV). These supersede the serverless-shaped items below where they
conflict.

- **Feed fallback, four distinct assertions (P2, P2a).** These supersede the
  single "never 5xx" line in the CEO-round section below, which contradicted
  P2 and would have driven the wrong assertion:
  1. rules-load failure, cache warm → **200** + cached body + counter
  2. ICS-library failure, cache warm → **200** + cached body + counter
  3. Postgres unreachable → **503** + `Retry-After` + counter (never 200 with
     stale events)
  4. any generation failure with a **cold cache** (post-restart, this home not
     yet regenerated) → **503** + `Retry-After` + counter
- **State survives container recreation (P1a).** Insert a row, `docker compose
  down` (without `-v`), `up`, read the row back. Also confirm Caddy does not
  re-issue certificates on a plain restart. Every other T-E1 assertion passes
  on a stack that loses all data, so this is the one that matters.
- **`subscribed_at` is set once (P1/C3).** Two feed fetches ≥6h apart set it;
  a third fetch does not move it. This supersedes the "analytics 'subscribed'
  fires once [on one fetch]" line in the Critical Paths section below, which
  encodes the definition C3 replaced.
- **Reboot-start (P6a).** Reboot the host; the stack returns with data intact
  and TLS serving.
- **Rollback rehearsal (P8a).** Deploy a deliberately broken image, then run
  the two written rollback commands and confirm the feed serves again. Confirm
  `pg_dump` ran before migrations.
- **Injectable clock (P4).** Assert `schedule.ts` and the feed generator never
  call `new Date()`. The golden-file test passes a frozen date and a pinned
  `DTSTAMP`, and must pass when run on two different days.
- **Client IP through the proxy (P3).** With Caddy in front, assert the rate
  limiter sees distinct client IPs from `X-Forwarded-For` rather than the proxy
  address. Two requests from different clients must not count as one.
- **304 writes a `feed_fetches` row (P5).** A conditional request answered with
  304 still logs the poll; the in-process hash map short-circuits before
  generation.
- **Compose stack smoke test (P1).** `docker compose up` on a clean host serves
  over TLS, migrations run before the server accepts traffic, and Postgres is
  not reachable on any published host port.
- **Restore rehearsal (P6).** Restore a `pg_dump` into a scratch database at
  least once. Not automatable, and not optional: premise 5's trust promise
  rests on it.

- **Rules registry resolves historical versions (X2).** Every `rule_version`
  referenced by a fixture resolves via `getRule(id, version)`; the version list
  is append-only; an unresolvable version renders the stored title with a
  "rule version unavailable" note rather than throwing.
- **Wizard rate limit and request logging (X3).** Home creation is capped per
  IP; every wizard route request is logged with hashed IP, user-agent, route,
  and timestamp.
- **Notification spike (Y1), before the scaffold ticket.** Hand-written ICS
  feed, hosted, subscribed from a real iPhone and a real Google account, with
  and without VALARM. Records whether all-day subscribed events notify at all.
  Not a unit test — a manual result written back into the plan.
- **Edit-token rotation (Y2).** Rotation mints a new edit token, re-derives
  feed and action, updates all three digests, and the old URLs 404. Assert no
  plaintext token is ever persisted.
- **Wizard start fires on first answer, not page load (Y4).** A landing-page
  request alone produces no `wizard_started` event; the first submitted answer
  produces exactly one.
- **`unresolved` task lifecycle (Y6).** Skipping "I'm not sure" yields an
  `unresolved` task that renders under "resolve later", has no `next_due`, and
  is absent from the feed; answering later moves it to `active` with a normal
  anchor or to `not_applicable`.
- **Answer-change reconciliation (Y7).** Changing answers adds newly
  applicable tasks, marks no-longer-applicable ones `not_applicable` without
  deleting them, preserves completion history on deactivated tasks, and
  restores that history on re-activation.

## Affected Pages/Routes
- `/` — landing + question 1 (merged, D1). Promise ~15 words, Q1 above the fold at 320px, no signup language beyond "Signup not required".
- `/wizard/*` — sectioned interview. Section-style progress (no fixed count), dwelling gate first, "I'm not sure" assist + non-blocking skip, live count bar (mobile) / two-column ledger (desktop ≥768px).
- `/plan/[editToken]` — result page. One ember CTA, by-area accordion, "commonly missed" badges, ≤2-surprise reframe, email capture (store-only, E10), PDF link, permalink behavior.
- `/calendar/[feedToken].ics` — subscribed feed. Discrete events, stable UIDs, ✓ on completed, ETag/304 (E12).
- `/task/[actionToken]/[taskId]` — task page from calendar event. Why + source, mark done, note, snooze, doesn't-apply, per-asset log.
- Lost-link screen — any invalid token route (uniform 404, E9).

## Key Interactions to Verify
- Answer → live task count animates old→new; screen reader announces (ARIA live, D17).
- First surprise gets its own beat; focus moves in and back (D8/D17).
- Mark done → success + next due date + calendar-lag sentence (D9); undo/unmark works.
- Second person taps same event after completion → already-done state with who/when + unmark (D6); exactly one completion row survives.
- Subscribe fallback (copy link + per-client instructions) always visible under primary CTA.
- Skip "not sure" → wizard still completes; "we couldn't tell" resolvable task appears.

## Edge Cases
- Condo profile end-to-end: never asked about gutters/sump pump; result headline reframes at ≤2 surprises (never "0 you didn't know").
- Month-length clamp: task due Jan 31 + 1 month → Feb 28 (E8).
- Local-date due badges: user at UTC-8 at 4pm — nothing flips overdue early (E8).
- Re-anchor: complete early → next occurrence anchors from completion date (E8).
- Double-submit wizard answer; back button mid-wizard; 30-min-stale page submit.
- Mark-done write failure → note text preserved, inline retry (E9).
- Analytics insert failure → user request still succeeds (E9).
- Feed regeneration keeps byte-identical UIDs (golden file, E11).
